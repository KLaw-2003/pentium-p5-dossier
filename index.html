1. Microarchitecture

The Pentium P5 keeps the x86 programming model while changing the internal implementation substantially. It is a two-way, in-order superscalar design: when two adjacent instructions satisfy the pairing rules, they can be issued together to the U and V integer pipelines.

Key organization

Integer issueUp to 2 instructions per cycle, in program order
Integer pipelinesU pipe and V pipe; U supports a broader set of operations
Pipeline stagesPF → D1 → D2 → E → WB
Register organizationShared x86 architectural register state; eight 32-bit general-purpose integer registers
Branch predictionDynamic prediction using a 256-entry, four-way set-associative Branch Target Buffer (BTB)
Floating pointSeparate pipelined x87 floating-point unit

Dual issue and pairing

Pairing is decided in D1. The hardware examines two adjacent instructions, I1 and I2. The basic pairing rule requires both instructions to be simple, requires I1 not to be a jump, and rejects register hazards such as RAW and WAW. The U/V resource restrictions must also be satisfied.

Simple instruction. In this context, “simple” means the instruction can be handled directly by hardwired control rather than requiring a microcode sequence.

Precise exceptions

Even though instructions overlap in the pipeline, the processor must preserve a precise architectural state. For the integer pipeline, exceptional conditions are resolved before write-back, because WB is the stage that updates architectural registers and flags.

2. Notable x86 ISA features

The P5 does not introduce a new ISA; its design challenge is to extract more instruction-level parallelism while remaining compatible with existing x86 software.

  • Variable-length instructions. The front end must identify instruction boundaries before two adjacent instructions can be decoded and considered for pairing.
  • Complex instructions and microcode. Common operations can use hardwired control, while more complex x86 instructions may require a microcode sequence.
  • Rich addressing modes. Memory operands may require effective-address generation in addition to the arithmetic or logical operation itself.
  • Backward compatibility. Existing x86 binaries remain valid even though the internal microarchitecture adds dual pipelines, prediction, and a redesigned memory system.

The distinction is important: ISA compatibility constrains externally visible behavior, not the internal hardware organization.

3. Memory system & memory consistency model

Cache organization

PropertyInstruction cacheData cache
Capacity8 KB8 KB
Associativity2-way set associative2-way set associative
Line size32 bytes32 bytes

The split I-cache/D-cache organization increases bandwidth: the front end can fetch instructions while the execution stage performs data accesses. The data cache is organized as eight interleaved banks. Two accesses to different banks can proceed together; if both accesses require the same bank, the U-pipe access has priority and the V pipe stalls for one clock.

Important distinction. Successful pairing in D1 does not guarantee stall-free execution. Pairing checks instruction and register constraints; cache-bank conflicts are detected later.

Memory consistency model (MCM)

The memory consistency model defines the order in which loads and stores become visible to software; it is different from cache organization. The Pentium and Intel486 follow Intel's processor-ordered model and behave as strongly ordered processors in most cases. Reads and writes normally appear on the system bus in program order, with a limited exception: a read miss may pass buffered writes when those writes are cache hits and do not target the same address. I/O reads and writes remain in program order.

Cache coherence answers whether processors agree on a memory location's value. Memory consistency answers which orderings of memory operations software is allowed to observe.

4. Performance characterization

The P5's performance improvement comes from several mechanisms working together rather than dual issue alone: instruction pairing, branch prediction, split caches, a wider external data path, and a pipelined floating-point unit.

  • Integer: the paper reports roughly 2× the performance of an i486 at the same clock rate in its comparisons.
  • Floating point: the paper reports much larger gains for some vector workloads, with up to about 5× at equal clock in selected cases.
  • Why less than the theoretical 2× issue rate? Not every adjacent pair is legal; branches, cache misses, and bank conflicts also create bubbles or stalls.

These measurements should be read as system-level results: compiler quality and memory-system differences also contribute to the observed speedup.
