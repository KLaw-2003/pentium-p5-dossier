1. Overview

The Intel Pentium P5, introduced in 1993, is a 32-bit x86 superscalar processor. It preserves x86 binary compatibility while adding two integer execution pipelines, dynamic branch prediction, split instruction and data caches, and a pipelined floating-point unit. The integer core uses in-order, dual-issue execution: up to two adjacent instructions may be issued in one cycle when the pairing rules are satisfied.[1]

2. Microarchitecture

U and V integer pipelines

Pentium duplicates key address-generation and integer execution resources to form two pipelines, U and V. The pipelines are asymmetric: U can execute a broader class of instructions, while V is restricted to simpler operations. When a legal pair is found, the first instruction is issued to U and the second to V.[1]

Register file organization

The processor retains the x86 architectural integer register model, including the eight 32-bit general-purpose registers EAX, EBX, ECX, EDX, ESI, EDI, EBP, and ESP. The U and V pipelines share the same architectural register state, so register dependencies directly constrain whether two instructions can be paired.[2]

Branch prediction

Pentium uses a dynamic branch predictor with a 256-entry, four-way set-associative Branch Target Buffer (BTB). The BTB stores branch target and history information so that the front end can continue fetching along a predicted path. A correct prediction avoids the normal taken-branch delay; a misprediction redirects fetching and discards work from the wrong path.[1]

3. ISA Features

Pentium does not introduce a new ISA; it implements the existing x86 ISA. Several x86 characteristics are especially important because they make wide fetch, decode, and superscalar issue more difficult.

  • Variable-length instructions. The front end must identify instruction boundaries before it can decode two instructions together.
  • Complex addressing modes. Memory operands require address generation in addition to the arithmetic or logical operation.
  • Hardwired and microcoded instructions. A “simple” instruction can be handled directly by normal hardwired pipeline control; more complex instructions require a microcode sequence.[1]
  • Backward compatibility. The internal microarchitecture changes substantially while the software-visible x86 behavior remains compatible with existing binaries.

The architecture paper reports that more than 90% of dynamically executed instructions in the Integer SPEC workloads were in the “simple” class.[1]

Instruction pairing

Pentium considers two consecutive instructions, I1 and I2. A normal pair requires:

  • both instructions are simple,
  • I1 is not a jump,
  • no RAW (read-after-write) dependency from I1 to I2,
  • no WAW (write-after-write) dependency, and
  • the required execution resources are compatible with the U/V organization.

If the checks fail, I1 issues alone; the in-order issue logic does not skip I2 to search farther ahead for a better pair. Compiler scheduling can therefore improve performance by placing independent instructions next to each other before execution.[1]

Precise exceptions

A precise exception leaves the architectural state corresponding to a well-defined point in program order: instructions before the faulting instruction appear completed, while later instructions have not changed visible state. In the Pentium integer pipeline, exceptional conditions must be resolved before an instruction is allowed to update registers and flags in the WB stage.[1]

Pentium separates the L1 instruction and data caches to increase bandwidth: the front end can fetch instructions while the execution pipelines access data. The data cache supports two address lookups through a dual-ported TLB/tag path, while the data array is divided into eight interleaved, single-ported banks. Two accesses to different banks can proceed in the same cycle; if U and V need the same bank, U proceeds and V stalls for one clock.[1]

Important: successful pairing in D1 does not guarantee stall-free execution later in the pipeline.

Memory consistency model (MCM)

The memory consistency model defines the ordering of memory operations that software may observe; it is different from cache organization. Intel describes the Pentium and Intel486 as following a processor-ordered memory model, while behaving as strongly ordered processors in most circumstances. Reads and writes normally appear at the system bus in program order, with a documented exception: a read miss may pass buffered writes when those writes are cache hits and are not to the address of the read miss. I/O reads and writes remain in program order.[3]

6. Performance Characterization

The architecture paper reports approximately 2× integer performance over the i486 in an equal-core-clock comparison and substantially larger floating-point gains. In the SPEC92 chart discussed in our presentation, the Pentium/i486DX2-66 ratios are approximately 2.0× for SPECint92 and 3.6× for SPECfp92; the paper separately reports gains of up to about 5× on some floating-point vector code.[1]

These gains should not be attributed to dual issue alone. They also reflect branch prediction, the split caches, a wider memory interface, the pipelined FPU, compiler scheduling, and workload characteristics. In practice, the theoretical two-instruction issue width is reduced by pairing restrictions, branches, cache misses, and bank conflicts.
